# Optional panel pinning

Requested by Marek after testing Dayline: keep the editor visible while moving to another application or monitor to copy text. Add optional pin-to-screen control.

Place a pin beside the preferences button. Pinning leaves the current popup above desktop windows and releases its modal grab so users can click other apps, use Alt+Tab, copy text, return and paste. The existing editor, date, caret/selection and unsaved contents must survive toggling. Pinned mode displays a small status hint and an explicit close button; clicking the panel indicator still toggles visibility. Unpinning restores ordinary popup outside-click dismissal. Pin state lasts only in this extension instance. System dialogs and screen locking retain GNOME's ability to dismiss the panel.

Implement a small `ui/pinning.js` controller attached after panel registration. Release the normal modal grab by closing without animation, detach only this menu from GNOME's panel menu manager, and reopen without a grab. Reverse these steps on unpin. Use the public addMenu/removeMenu methods; never replace global functions, patch other menus or change GNOME's unsafe-mode setting. Dispose signal connections with the panel. Nonmodal close must release any Shell text focus.

Load the new controller into the already-running panel through Looking Glass for this update; this preserves the editor and avoids reloading cached existing modules. Future sessions attach it from `extension.js` automatically. Validate the exact live-attachment command in an isolated session.

Verify in real GNOME 50: normal modal behavior, pin/unpin with an active multiline editor, focus another real test window, return/paste, preserved editor identity/text/date/selection, explicit close, reopening pinned, and disabling while pinned without leaving a modal grab or menu registration. Existing domain/storage/UI tests must still pass. Ship to the existing public repository and install without touching personal data.

## Status and opacity

User requested In progress as a third status, plus a green top-bar count of today's in-progress tasks and a separate count of today's waiting tasks. Done is excluded from both. Play/Pause switches waiting/in-progress; the existing checkbox completes/reopens. Completion clears in-progress, reopening returns to waiting. A strict version-2 document adds `inProgress`; strict original v1 input is migrated without rewriting user text and its original valid bytes are retained as the previous-copy backup on save.

Preferences expose background opacity 20–100%, default 100%. Only the popup frame background becomes transparent; text and controls retain full opacity for readability.

## Private notes

The approved fourth tab, Private, stores notes in a separate encrypted vault at `$XDG_DATA_HOME/dayline/private-notes.vault` (normally `~/.local/share/dayline/private-notes.vault`). Its independent password creates/unlocks the vault. Use AES-256-GCM authenticated encryption with a key derived by scrypt (`N=131072`, `r=8`, `p=1`); never add Private notes to the ordinary document, export, import, or backup. There is no password recovery. Users can back up the encrypted vault file separately and must retain the password.

Lock and clear decrypted private contents whenever the popup actually closes and whenever the screen locks. The temporary close/reopen needed to switch pin mode must preserve the unlocked vault. Disable/reload also disposes unlocked state. UI must stay responsive while the Python cryptography backend runs. Write the vault atomically with private file permissions, preserve the prior encrypted file after any failed operation, reject wrong passwords or modified ciphertext, and keep the password out of subprocess arguments and logs.

Ship `vault.js`, `private_vault.py` and the Private widget in the ordinary extension install, immutable runtime snapshot and distributable archive. Python backend contents affect the runtime hash. Use system Python 3 with `python3-cryptography` on Ubuntu; document that dependency and install it in CI. The release remains 0.2.0.
